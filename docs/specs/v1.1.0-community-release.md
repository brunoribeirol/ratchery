# Delta Spec: Ratchetry v1.1.0 community release

Mode: **openspec-light** (T1/T2 default).

## Why

The community-first onboarding merged after `v1.0.0`, so the supported release
artifact still requires the older onboarding path. Publish those backward-compatible
capabilities as `v1.1.0` before creating a Homebrew formula or starting another
integration experiment. The repository's tracked deployed hook must also match the
hook source included in the same release.

## What changes

- Promote the current `Unreleased` onboarding changes to dated `v1.1.0` release notes.
- Bump the CLI, hook source, tracked deployed hook, manifest, stable-line documentation,
  and immutable reusable-Action example to `1.1.0`/`v1.1.0`.
- Add a regression assertion that the repository's tracked deployed hook is byte-equal
  to `lib/hook_runtime.py`.
- Prepare, but do not create, the signed tag and GitHub Release transaction.

## Affected contracts

- CLI and manifest version: `1.1.0`.
- Release tag and archive prefix: `v1.1.0` / `ratchery-1.1.0`.
- Reusable Action documentation: exact immutable `brunoribeirol/ratchery@v1.1.0`.
- Tracked self-hosted hook snapshot: byte-equal to the shipped hook source.

## Out of scope

- No `ai-memory`, Kiro, MCP, daemon, dependency, or default-tool integration.
- No tag, GitHub Release, Homebrew repository, or OpenSSF attestation is created by
  the source PR itself.
- Published `v1.0.0` and `v1.0.0-rc.1` tags remain immutable.
